# ADR 0001 — TUI 回看交互采用键盘驱动 vline（路线 D）

**状态**：已接受
**日期**：2026-07-04

## 背景

TUI 的核心特性是"可回看"——光标移到任意历史 K 线，侧栏显示那天的完整诊断（指标数值 + 评分信号）。

调研文档（`doc/TUI_K线分析工具_技术调研.md`）推荐 `textual-plotext` 的 `PlotextPlot`，并乐观暗示鼠标交互可用。但 `PlotextPlot` 将 plotext 画布渲染为静态图，**不暴露数据坐标系**：只能拿到 Textual 的 `MouseMove` 事件给出的终端 (row, col) 坐标。从终端坐标反推"第几根 K 线"需要逆向 plotext 的内部布局（边距随终端宽度漂移、画布会自动抽样压缩），脆弱且 resize 后易失效。

此外终端 K 线密度高（~200 根挤在 80 列，单根不到半字符宽），鼠标精度无法对准单根 K 线。

## 决策

采用**路线 D**：plotext 画 K 线（保留 `candlestick()` 现成函数），回看用**键盘 ←→ 驱动**一个 `cursor_date` 状态，在图上叠加 plotext 原生 `vline(x=cursor_date)` 标记当前选中 K 线，侧栏调 `analyze(df.loc[:cursor_date])` 刷新。

不依赖 (row,col)→数据索引 的反推，因为 `vline` 按数据坐标定位，不是终端坐标。鼠标留给"点击切标的/切分类"等离散交互。

## 备选方案

- **路线 A**（纯键盘 + 自叠高亮柱）：要在 plotexr 画布上操作像素画高亮柱，比 `vline` 麻烦。
- **路线 B**（鼠标 + 自写反映射）：脆弱，resize/重排后易错位。否决。
- **路线 C**（Textual Canvas 自绘 K 线）：坐标系完全自控，映射精确，但放弃 plotext 的 `candlestick()` 现成函数，等于重造轮子。

## 后果

- 优点：回看交互干净、精准，不依赖脆弱的坐标反推；plotext 负责画图省力。
- 风险：`vline` + `candlestick` 同图叠加在终端渲染下是否清晰（竖线与 K 线柱是否糊在一起）**未实测**，是本路线唯一不确定性，需在原型阶段验证。
- 限制：鼠标无法悬停查单根 K 线，用户须用键盘。终端 TUI 的正道是键盘，此限制可接受。
