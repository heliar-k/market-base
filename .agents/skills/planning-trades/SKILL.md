# 交易计划（trade-journal + 策略工具）

**先查策略登记表**，选策略后进对应分支。工具脚本已有完整输出逻辑，skill 只负责：何时用哪个、怎么跑、怎么解读、怎么记录。

## 策略登记表

| 策略 | 分支 | 入口 | 用途 |
|---|---|---|---|
| 方向性交易（做多/做空挂单） | A | 手写流程 | 事件驱动的挂单计划，写入 trade-journal/ |
| 盘前快照（实时价 + OI 墙） | A/C 共用 | `uv run python -m src.stock_snapshot {X} --oi` | 盘前/盘后实时价、昨收、期权 OI 墙（阶段 2 步骤 1/4） |
| Sell Put 收租 | B | `uv run python src/sell_put.py --symbol {X}` | 选卖 put 点位（期权墙 + 技术面交叉） |
| 下跌保护/对冲 | C | `uv run python src/hedge_planner.py --symbol {X}` | 持仓保护结构比价（裸 put / 价差 / 领口） |
| GEX/期权墙验证 | D | `uv run python src/compute_gex.py --symbol {X} --port 4001 --batch-size 50` | 支撑/阻力/磁吸墙验证（A/B 共用） |

> 新策略脚本出现时：登记表加一行（入口命令 + 一行用途），逻辑留在脚本里，不搬进 skill。

## 分支 A：方向性交易计划

产出格式固定的 Markdown 文档，写入**仓库根 `trade-journal/` 目录**，文件名 `YYYY-MM-DD_{SYMBOL}_{方向}_plan.md`。
**一份文件一个标的**；同板块多标的同日分析 → 各自成文，文件头部互相引用并注明二选一/预算拆分关系（生命周期按文件管理，合并文件表达不了"一半失效一半有效"）。
**先读范例**：`trade-journal/2026-07-31_MU_SNDK_short_plan.md` — 格式照抄，方向互换即可（做多挂支撑位、做空挂阻力位）。注意该范例是合并文件，新计划按上文**一份文件一个标的**拆分。

### 阶段 1：计划生成

输入：标的 + 方向。用户只给标的时候，先 web_search 找催化剂再定方向。

1. **催化剂** — web_search / 用户信息，写清行情为什么发生（财报、消息、板块事件）。判断性质：趋势反转 or 事件兑现后的技术性回落/反弹 → 后者**仓位减半**。
   - **事件截止日**：财报/Investor Day 等日期写进计划文件顶部，并用 `LoopCreate`（cron，一次性 maxFires=1，触发日北京 ~18:00）设提醒："X 收盘前必须平仓"。⚠️ loop 仅在当前 pi 会话存活期间生效，跨会话失效——**真正的兜底是计划文件顶部的截止日**（阶段 2 步骤 3 每次盘前复核都会查），loop 只是备份。
   - **做空成本**（仅做空）：用 `yf.Ticker({X}).info` 查 `shortRatio`/`sharesShort`/`shortPercentOfFloat` 空头数据，写进计划（空头拥挤 → 轧空风险，仓位再减半或提示用户）；borrowRate 雅虎无公开数据，以券商显示为准；拿不到就注明"未评估"。
2. **技术快照** — 跑 `uv run python -m src.analyze data/stocks/{SYMBOL}.csv`（指数用 `data/indices/`）。摘 MA/RSI/MACD/Stoch/ATR/SuperTrend 关键值。数据缺失先 `./bin/fetch_ibkr --symbols {SYMBOL}`。
3. **挂单阶梯** — 表格：批次 | 挂单价 | 股数 | 依据。依据必须是具体技术位（MA 带、布林中轨、前高/前低），2 档起步，第一档挂最硬的位置。
   - **分时验证**（入场/止损位定稿前必跑）：`uv run python -m src.intraday_levels {SYMBOL} --date {前一日} --levels {候选入场,止损位}`。判读：①触及次数 ≥10 = 平台（真实供应/支撑），≤3 = 插针（扫荡位，止损挂插针高点外侧 +0.5% 以上，防二次扫）；②量能分布最大 bucket = 筹码货架，做空入场挂货架下沿、止损放货架上沿之外；③高点性质报"插针" → 昨高上方是止损密集区，禁止把止损贴在昨高 +0.5% 以内。
4. **风控** — 均价、止损、目标 1/目标 2、风险回报比（**≥2:1**）；写失效条件（如"开盘放量站稳 X 上方 → 撤单"）。
   - **仓位公式**（每次计算，不拍脑袋）：`股数 = 风险预算 ÷ |入场价 − 止损价|`；风险预算默认**账户权益 0.5–1%**（数值须用户确认）。多标的同日计划 → 预算按比例拆分，总风险 ≤ 1%。
   - **止损下限**：止损距入场 **≥ 0.5×ATR**（否则日内噪声秒穿，参考 8/6 教训：止损 895 距均价 20 点 ≈ 0.24 ATR 被一根反弹 bar 扫掉）；例外：止损位外侧有 OI 墙互证可收窄，但必须写明依据。
   - **持仓周期**（每笔必填）：超短（当日~2 天：事件兑现/0DTE/GEX 结构驱动）／波段（1–2 周：需更低高点 + 日线破位结构）／趋势（数周+：需周线反转确认）。逆大势（长期升势、卖方抬目标价）的反弹做空**默认超短**，必须配**时间止损**（成交后 N 日内未破 X → 无条件平仓，不等价格止损）；GEX/OI 墙有效期 ≤1 天，不得作为多日持仓依据。
   - **规则冲突时**（高波动票常见，如 0.5×ATR 止损导致 R:R 不足 2:1）：**优先保 R:R ≥ 2:1**，用 OI 墙/前高例外收窄止损并写明依据；收窄后仍不满足 → 放弃该交易，不硬做。
5. **执行规则** — ≤6 条本次纪律：衰竭/企稳确认、同板块二选一、财报/周末事件风险、止损一刀切。具体到本次标的，不写套话。
6. **保存** — 文件名含日期（北京时间）。文件顶部加**状态行**（`状态：active`），并注明同标的上一个计划文件的相对路径（上一篇）。同标的上一个 active 计划 → 走阶段 2 追加，不新建（用户明确要求"另起一篇"时：旧文件状态行改为 `closed`（已平仓）或 `stale`（已失效）+ 一行结论，再新建）。

**完成标准**：每个挂单点有技术依据；每个持仓有止损+目标+失效条件；R:R ≥ 2:1；执行规则覆盖财报/周末/板块联动风险；股数由仓位公式算出（用户在阶段 1.5 确认）。

### 阶段 1.5：用户确认（计划生成后、挂单前）

计划文档生成后，**必须**逐项列出以下参数给用户确认，用户回复后才算计划成立：① 挂哪几档（默认只挂第一档）② 每档股数 ③ 风险预算/账户权益占比 ④ 止损位。用户调整 → 改计划文档后重列。未确认前不得进入阶段 2。

### 阶段 2：盘前复核（美东盘前，北京 ~19:00）

**先做计划有效性检查**：现价（`uv run python -m src.stock_snapshot {SYMBOL}`）是否已越过挂单档位？已越过且无回踩 → 计划失效，文件状态行改 `stale`，重新走阶段 1，不复核旧档。

打开已有计划文件，**追加**复核结果，保留原计划不改写。

1. **实时价** — `uv run python -m src.stock_snapshot {SYMBOL} QQQ SPY`：昨收/盘前现价/距昨收/昨交易日区间；顺带 QQQ/SPY 大盘方向（逆势则加重仓位减半）。代理断 → 报错，降级用 data/stocks/{SYMBOL}.csv 最新收盘。
2. **关键走势** — `uv run python -m src.intraday_levels {SYMBOL} --levels {挂单价,昨高,昨低}`（需要逐 bar 明细加 `--above {位}`）：开盘冲高到哪、回落哪、关键位被测试几次。**两次测试未站稳 → 阻力/支撑有效，计划成立**；候选入场位触及次数 ≥10 且量能为最大 bucket → 平台验证通过。
3. **新消息** — 财报日期、目标价调整、评级。⚠️ 距财报 <3 个交易日 → 持仓不得跨财报。
4. **期权墙验证** — `uv run python -m src.stock_snapshot {SYMBOL} --oi`（yfinance 隔夜 OI，注明无 IV/无 bid-ask）：最大 put 墙（支撑/目标）、最大 call 墙（阻力/止损）。止损位外侧有 OI 墙 = 止损不易被秒穿；入场位骑在墙上 = 有 dealer 对冲托底/压制 → 重新评估该入场。
5. **GEX 验证** — 走分支 D。最大正 GEX = 磁吸/支撑；负 gamma 区 = 加速。
6. **结论与操作** — 先列**用户决定**（挂/不挂、保留/撤单），再给开盘三种情况表（放量突破→撤单 / 冲高回落→成交持有 / 低开→不追），最后勾选复核清单。

**完成标准**：每个挂单点的存废都有技术+期权+消息面三重依据；清单未勾完不给结论；"用户决定"行必须来自用户本人确认。

### 阶段 3：持仓监控（成交后，盘中）

计划成交后进入本阶段，每个盘中决策（止损上移/兑现/加仓）都要**追加**到计划文件（时间戳 + 依据）。

1. **GEX 重算时机** — spot 较入场动 1%+ → 重跑 `compute_gex.py`（或 `--reuse-greeks`），结构与入场时对比，变化写进文件。
2. **止损上移规则** — 止损只上移不下移；上移依据：GEX 墙转正、均线回踩确认、浮盈 ≥ 2×剩余风险。上移后距现价仍须 ≥ 0.5×ATR。
3. **兑现规则** — 目标 1 挂单优先；浮盈 ≥ 1×风险预算时允许主动分批锁利（参考 8/6 教训：浮盈 $1,292 未锁一半，反弹全回吐）。
4. **不加仓** — 反弹越过第二档/浮盈回吐超过 50% 等情形禁止摊平；加仓只按原计划阶梯执行。
5. **大盘突变** — QQQ/SPY 单日 ±2%+ 或板块异动（如同业财报）→ 重新评估持仓，决策写入文件。

**完成标准**：每个盘中决策有时间戳 + 依据；止损位移有 GEX/技术面支撑；GEX 结构与入场时对比过。

### 阶段 4：平仓复盘（离场后必做）

仓位全部了结后，在计划文件末尾追加**复盘**（原计划保留）：

1. **执行记录** — 成交价/时间、每笔盈亏、浮盈峰值与回吐、离场方式（止损/止盈/手动）。
2. **教训** — 本次最痛的一个失误 + 一个做对的事，写成一句话，**并复制为下一份计划"执行规则"第 1 条**（skill 不自动跨文件传承，靠这个桥接）。
3. **状态行更新** — `active` → `closed`（+ 一行结论：盈亏/教训）。

**完成标准**：文件状态行已改 closed；教训已写入下一计划或明确说"下次不用"。

## 分支 B：Sell Put 收租

1. **前置** — `data/stocks/{SYMBOL}.csv` 存在（缺则 `./bin/fetch_ibkr --symbols {SYMBOL}`）；脚本会自动复用当日 GEX 数据，没有则自动调 compute_gex 拉取。
2. **运行** — `uv run python src/sell_put.py --symbol {SYMBOL}`；当天重跑默认复用，`--fetch` 强制重拉，TWS 实盘加 `--port 4001 --batch-size 50`。
3. **解读** — 输出为 markdown 报告：
   - **当前状态**：⚠️ 破位中（close < MA20 且 < MA60）→ 结论等企稳（站回 MA20 或 RSI 拐头上 40），不硬推
   - **主选** = 中端（DTE 51–141）OI 最大；**近端**（DTE ≤ 50）距现价 <1x ATR 的被标为不推荐；**保守档** = 远端（>141）距现价 ≥8% 且年化最高
   - 净 GEX < 0 → dealer 做空 gamma、波动放大，收租环境变差
4. **记录** — 候选点位 + 结论给用户决策；成交的挂单记入 `trade-journal/` 对应日期的计划文档（格式照分支 A）。

**完成标准**：报告结论与"当前状态"的破位/健康判断一致；给用户的推荐明确到具体行权价 + 到期日。

## 分支 C：下跌保护/对冲

1. **运行** — `uv run python src/hedge_planner.py --symbol {SYMBOL}`（默认自动挑 30/60/90 天到期、现价下方 2.5–10% put、上方 10–12.5% call；可 `--exps/--puts/--calls` 指定）。
2. **解读** — 三类结构对比，成本均为 mid 价近似（实际看挂单深度）：
   - **裸买 put**：保护不封顶，最贵
   - **put 价差**（买高卖低）：区间封顶，便宜 ~40%
   - **领口**（买 put + 卖 call）：最便宜，成本为负 = 净收入，代价是上行封顶
3. **建议** — 按用户需求给三选一：求最大保护 → 裸 put；成本敏感且接受区间 → 价差；有持仓且愿封顶上行 → 领口。附带财报日历提醒（脚本会打印，拿不到不阻塞）。

**完成标准**：建议明确到具体结构 + 行权价组合 + 每股成本；说明该结构的代价（封顶/区间）。

## 分支 D：GEX/期权墙验证

1. **运行** — `uv run python src/compute_gex.py --symbol {SYMBOL} --port 4001 --batch-size 50`；当天重跑加 `--reuse-greeks`（spot 动 1%+ 需重拉快照）；TWS 未开 → 自动降级 yfinance（IV 反推 gamma，注明精度下降）。
2. **解读** —
   - 最大正 GEX 行权价 = dealer 做多 gamma = **支撑/磁吸墙**
   - 最大负 GEX / Gamma Flip 区（正转负过渡）= **阻力/加速区**
   - 净 GEX > 0 → 波动被抑制（做空环境差）；净 GEX < 0 → 波动放大
3. **用法** — 只作验证不作主导：技术位定入场，GEX/OI 墙验证或否决（止损位外侧有墙 = 不易被秒穿）。
4. **失效条件（何时不信 GEX）** — 以下情况 GEX 结论降权或重算：
   - spot 较上次计算动 **1%+** → 必须重算（结构已失真）
   - **净 GEX 正负翻转** → 结构反转，旧结论作废（参考 8/6：净 GEX 转负后价格仍涨，短期 gamma 对日内反转预测力有限，不单靠它决定止盈时点）
   - yfinance 降级路径（BS gamma + IV）→ 精度低于 IBKR，只用于验证不用于主导
   - 到期日 < 2 天 → 近月墙快速衰减，看次月

**完成标准**：输出中标注数据来源（IBKR 或 yfinance 降级）与净 GEX 方向；给出一句对当前计划的验证结论。

## 通用要求

- 数据标时间与来源（"数据截止：X 收盘"）；盘前价标注基准（盘后价）。
- 数值精确到挂单价/行权价/止损位，不写"逢低做多"类模糊指令。
- 工具失败（TWS 未开/代理断）→ 文档注明降级路径，不阻塞流程。
- 期权/GEX 只作验证不作主导；语言用中文。
